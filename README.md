# Moby × KOPI — демо

Демо-прототип банковского приложения в стиле Moby со встроенной копилкой [KOPI](https://github.com/jimparkby/mtb): каждая оплата картой округляется вверх, сдача копится и одним пакетом покупает BTC, ETH или консервативный рублёвый инструмент по реальному курсу.

Бэкенд — тот же, что в [jimparkby/mtb](https://github.com/jimparkby/mtb), плюс счёт карты: остаток, пополнения и лента операций. Фронтенд переделан под интерфейс банковского приложения.

## Экраны

Референсы интерфейса лежат в [`docs/screens`](docs/screens).

| Экран | Что в демо |
|-------|------------|
| **Главная** | Имя, карта Prime Line BYN, остаток (скрывается «глазом»), кнопки Пополнить / Перевести / Оплатить, последняя операция, баннер «Копилка KOPI» с живой суммой портфеля, промо «Округляй и копи», счёт KOPI с доходностью |
| **Оплатить** | Шторка-эмулятор кассы: пресеты покупок, чек «покупка → округлено → списано → в копилку». С карты списывается покупка вместе со сдачей |
| **Пополнить** | Шторка пополнения карты (эмулируется) |
| **Продукты** | Карусель баннеров, Карты и счета, Кредиты, Вклады, **Инвестиции со сдачи** (NEW), Заявки на продукты |
| **Чат** | Чат-помощник: отвечает про копилку, округление, курс BTC/ETH, баланс и цель по данным пользователя |
| **Ещё** | Настройки (настройки копилки), Уведомления, Курсы валют (живой BTC/ETH/USD), KOPI, Обменник, О демо |
| **Копилка KOPI** | Портфель с графиком за час и бейджем Live, копилка и «Купить сейчас», цель с прогнозом, история округлений и покупок |

Прямые ссылки для QR: `#kopi`, `#pay`, `#topup`, `#products`, `#chat`, `#more`, `#rates`.

Каждый посетитель получает свою копию данных Ивана (гостевая сессия на неделю), поэтому весь зал может нажимать одновременно. «Начать демо заново» в настройках копилки возвращает исходную неделю покупок и остаток.

## Что добавлено к бэкенду KOPI

- **Счёт карты.** `users.balance` и таблица `topups` (миграция 5). Оплата списывает со счёта покупку и сдачу; если денег не хватает — `400 Недостаточно средств на карте`.
- **Пополнение:** `POST /api/topups` `{ amount: "50", title? }`, до 10 000 BYN за раз.
- **`GET /api/state`** дополнительно отдаёт `account` (остаток, продукт, last4) и `feed` — ленту операций по карте.
- Демо-неделя начинается с зарплаты 1 450 BYN и заканчивается переводом PEREVOD BSB +25 BYN.

## Запуск

Нужен Node.js 24.

```bash
npm install
npm start          # http://localhost:3000
npm run dev        # с перезапуском при изменениях
npm test           # тесты на SQLite и на PostgreSQL (PGlite, ставится как dev-зависимость)
```

## Переменные окружения

| Переменная | Что делает |
|------------|------------|
| `PORT` | порт, по умолчанию 3000 |
| `DATABASE_URL` | PostgreSQL (`postgres://…`). Если не задан — SQLite |
| `PGSSL` | `true`, если Postgres требует SSL (внешний адрес Railway) |
| `DB_PATH` | путь к файлу SQLite, по умолчанию `data/kopi.db` или volume Railway |

## База данных

| Таблица     | Что хранит |
|-------------|------------|
| `users`     | демо-пользователи: общий (`guest = 0`) и гостевые копии посетителей (`guest = 1`) |
| `sessions`  | SHA-256 токенов гостевых сессий и срок действия |
| `settings`  | шаг округления, множитель, актив, порог пакетной покупки |
| `goals`     | цель накопления (название, сумма) |
| `payments`  | оплаты: сумма, округление, сдача; `purchase_id` пуст, пока сдача в копилке |
| `purchases` | пакетные покупки: актив, сумма, курс, количество, статус (`pending` → `charged` → `filled`) |
| `topups`    | пополнения счёта карты; остаток — `users.balance` |
| `rates`     | история курсов BTC/ETH в BYN (раз в минуту) |
| `schema_migrations` | применённые миграции |

Таблицы `cards` и `ingest_tokens` создаются миграциями для совместимости с веткой `accounts` и здесь не используются. Копилка — это сдача по оплатам без `purchase_id`. Все суммы — в копейках (целые числа).

## API

Сайт сам берёт гостевой токен и шлёт его в `Authorization: Bearer <token>`. Без токена запросы работают с общим демо-пользователем.

| Метод | Путь | Описание |
|-------|------|----------|
| POST  | `/api/auth/guest` | своя копия демо → `{ token, user }` |
| POST  | `/api/auth/logout` | завершить гостевую сессию |
| GET   | `/api/state` | всё состояние дашборда |
| GET   | `/api/rates[?refresh]` | текущий курс |
| GET   | `/api/ticks` | курс за последний час для графика |
| POST  | `/api/payments` | `{ merchant, amount: "6,40" }` — эмулятор кассы, списывает покупку и сдачу с карты |
| POST  | `/api/topups` | `{ amount: "50", title? }` — пополнить карту |
| POST  | `/api/purchases` | купить сейчас на всю копилку |
| PATCH | `/api/settings` | `{ round_step, multiplier, asset, threshold }` |
| PUT   | `/api/goal` | `{ name, target }` (target в копейках) |
| POST  | `/api/reset` | вернуть демо-данные (только своей копии) |

## Деплой на Railway

Сервис собирается из репозитория без настройки (`railway.json`: старт `npm start`, healthcheck `/api/health`).

- **SQLite (как сейчас):** к сервису подключается volume, например с путём `/data`, сервер кладёт `kopi.db` в `RAILWAY_VOLUME_MOUNT_PATH`. Существующая база обновится миграциями при первом запуске.
- **PostgreSQL:** добавьте в проект Railway Postgres и передайте сервису `DATABASE_URL=${{Postgres.DATABASE_URL}}`. Таблицы создадутся сами. Данные из SQLite автоматически не переносятся — демо создастся заново.
